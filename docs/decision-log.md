# Decision Log

## ADR-001

- 결정: core 모듈은 Spring 의존성 없이 유지한다.
- 이유: 라이브러리 사용 범위를 넓히고 테스트를 단순하게 유지하기 위해서다.

## ADR-002

- 결정: Spring 연동은 별도 모듈로 분리한다.
- 이유: 순수 Java 사용 방식과 Spring 사용 방식을 분리해 API 표면을 명확하게 유지하기 위해서다.

## ADR-003

- 결정: Slack·Discord 전송에 채널당 기본 10초 제한을 적용하고, `(String, HttpClient, Duration)` 생성자로 조정한다. 기존 공개 시그니처는 유지한다.
- 이유: 동기 전송이 응답을 무제한으로 기다리면서 호출 스레드를 점유하는 것을 막기 위해서다. 이 기본값은 이전 무제한 대기 동작을 변경한다.
- 구현: 호출 API는 동기식으로 유지하되, `sendAsync`가 반환한 원래 future를 제한 시간 동안 기다린다. Java 17의 `HttpRequest.timeout`은 응답 헤더까지만 보호하므로, 완전한 본문 수신에도 별도 대기 제한이 필요하다. timeout·인터럽트 시 같은 future를 취소한다. 별도 실행기나 외부 의존성은 추가하지 않는다.
- 호환성: 기존 `IllegalStateException` 래핑과 I/O 원인, 인터럽트 플래그 복원을 유지한다. 주입하는 `HttpClient`는 `sendAsync`를 지원해야 한다.
- 범위: 자동 재시도, 비동기 공개 API, notifier 전체의 공통 deadline은 추가하지 않는다. 서버가 이미 처리한 메시지는 취소할 수 없으므로 실패 이후 재전송 판단은 호출자가 담당한다.
- 검증: 실제 loopback HTTP 서버로 헤더 지연, 본문 중단, HTTP 429/500, 연결 종료, 인터럽트, 정상 전송을 재현한다.
